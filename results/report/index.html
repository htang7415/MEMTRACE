Serving: engines and routing

Containers on macOS cannot reach the Metal GPU, so vllm-metal runs on the host and joins an llm-d inference pool through a relay pod, next to a CPU tier and an optional hosted tier. The first question is which engine serves the GPU tier; the second is how the scheduler should spread traffic.

Agent KV: how a provider's cache behaves

The GitHub Copilot coding-agent traces record, for every LLM call over a week, the prompt, cached, and completion tokens and the timing. A later call in a session repeats most of the previous prompt, so most of it could be served from cache. The reusable prefix of a call is the part that repeats the previous prompt (same model, prompt not compacted).

How long to keep it

If every call reached the replica holding its cache, a fixed cache lifetime would decide what is kept. Longer lifetimes keep more, but the memory needed grows much faster than the reuse.

What buys the most reuse

A trace-driven simulator replays one weekday of the traces (1.7 million calls) over 64 replicas, each with a GPU cache and optional host-RAM and SSD tiers. Its routers are idealized: session-key hashes the session; sticky returns to the replica it last used (a simplified llm-d approximate index); kv-aware knows exactly where the cache is.

Does the simulator match a real engine?

KV offloading cannot run on vllm-metal, so the tiers and routers above exist only in simulation. What can be checked is the core: one real replica with a fixed cache, fed Copilot sessions at their real gaps, against the simulator's prediction made before the run.

Scope

  • One machine: no datacenter GPUs and no multi-node scale; Qwen3-0.6B for most results.
  • The CPU tier is simulated in every mixed-pool result, and the host often paged, so differences under ~15% are not claimed.
  • The provider's cache counts come from one unnamed provider, which also shares prefixes across sessions.
  • The KV simulator is idealized: one cached prefix per session, no prefixes shared across sessions, no queueing; memory tiers use nominal bandwidths.
